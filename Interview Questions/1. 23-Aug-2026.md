<details markdown="1">
<summary><strong>Difference between NACL & SG.</strong></summary>

**Answer:**

| Feature | Security Group (SG) | Network ACL (NACL) |
| :--- | :--- | :--- |
| **Level** | Instance level (EC2, ENI, ALB) | Subnet level (Acts as a subnet firewall) |
| **State** | **Stateful** (Inbound return traffic is automatically allowed outbound) | **Stateless** (Outbound return traffic must be explicitly defined in outbound rules) |
| **Rule Type** | **Allow rules only** (Default denies everything not explicitly allowed) | **Allow and Deny rules** |
| **Evaluation** | All rules are evaluated before deciding to permit traffic | Rules are evaluated in strict **numerical order** (lowest number first) |
| **Default** | Default SG allows all outbound and blocks all inbound | Default NACL allows all inbound and outbound traffic |
</details>

<summary><strong>Task to patch an EC2 instance which is in a private subnet.</strong></summary>

**Answer:**
To patch an EC2 instance in a private subnet without exposing it to the public internet:
1. **Outbound Internet Connectivity:** Configure a **NAT Gateway** in a public subnet and add a default route (`0.0.0.0/0 -> nat-gateway-id`) to the private subnet route table so the instance can download OS update packages (`yum update` / `apt upgrade`).
2. **AWS Systems Manager (SSM) Patch Manager (Zero Internet / Private Way):**
   - Attach the IAM role `AmazonSSMManagedInstanceCore` to the EC2 instance.
   - Configure **VPC Endpoints (PrivateLink)** for SSM (`ssm`, `ssmmessages`, `ec2messages`) so SSM traffic never traverses the public internet.
   - Use **AWS Systems Manager Patch Manager** with an approved Patch Baseline to scan and automatically install missing patches during a scheduled maintenance window without needing SSH access or bastion hosts.
</details>

<details markdown="1">
<summary><strong>S3 Endpoints.</strong></summary>

**Answer:**
S3 Endpoints enable private connectivity between your Amazon VPC and Amazon S3 without requiring an Internet Gateway, NAT Gateway, VPN, or Direct Connect.
*   **Gateway Endpoint (Free):** Implemented via a routing entry in the VPC Route Table targeting `pl-xxxxxx` (AWS S3 Prefix List). Highly recommended for high-throughput, internal VPC-to-S3 traffic.
*   **Interface Endpoint (PrivateLink - Paid per hour + data processing):** Creates an Elastic Network Interface (ENI) with a private IP inside your subnet. Allows access to S3 from on-premises networks via VPN/Direct Connect or from peered VPCs.
</details>

<details markdown="1">
<summary><strong>Are S3 Endpoints cached locally?</strong></summary>

**Answer:**
*   **Gateway Endpoints:** No, they operate as route table prefix list entries evaluated directly by VPC software-defined networking routers.
*   **Interface Endpoints:** DNS resolution maps `s3.<region>.amazonaws.com` to private ENI IP addresses. DNS resolvers (such as Amazon Route 53 Resolver / CoreDNS) cache DNS query records based on the TTL (Time to Live) of the DNS record.
</details>

<details markdown="1">

*   **Interface Endpoints:** Supported for over 100+ AWS services (ECR, SSM, Secrets Manager, CloudWatch, SQS, SNS) powered by AWS PrivateLink with private ENIs and security group enforcement.
</details>

<details markdown="1">
<summary><strong>What are the layers in Docker?</strong></summary>

**Answer:**
Each instruction in a `Dockerfile` (`FROM`, `RUN`, `COPY`, `ADD`) creates an immutable, read-only filesystem layer.
*   **Layer Caching:** Docker caches unchanged layers. If a layer changes, all subsequent layers are rebuilt.
*   **Union File System (Overlay2):** Stacks all read-only image layers together and adds a single thin, writable **Container Layer** on top when a container runs.
*   **Best Practice:** Combine multiple `RUN` commands with `&& \` and clean up package caches (`rm -rf /var/lib/apt/lists/*`) in the same layer to minimize final image size.
</details>

<details markdown="1">
<summary><strong>Why use ENTRYPOINT & not CMD?</strong></summary>

**Answer:**
*   **`CMD`:** Sets default arguments or a default command that can be **completely overridden** by command-line arguments passed when running `docker run <image> <new_command>`.
*   **`ENTRYPOINT`:** Sets the **fixed executable process** that will always run when the container starts. Any CLI arguments passed to `docker run` are appended as arguments to the `ENTRYPOINT`.
*   **Best Practice Pattern:** Use `ENTRYPOINT` to define the binary (e.g., `ENTRYPOINT ["nginx"]`) and `CMD` to provide default parameters (e.g., `CMD ["-g", "daemon off;"]`), allowing users to easily customize flags while keeping the container purpose fixed.
</details>

<details markdown="1">
<summary><strong>Explain multistage Dockerfile.</strong></summary>

**Answer:**
A multi-stage `Dockerfile` uses multiple `FROM` instructions to separate the **build environment** (which contains compilers, SDKs, Maven/Gradle, Git) from the **final runtime environment** (which contains only the compiled binary and runtime dependencies).

```dockerfile
# Stage 1: Build stage
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn clean package -DskipTests

# Stage 2: Production runtime stage
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
COPY --from=builder /app/target/app.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```
**Benefits:** Reduces image size drastically (e.g., from 800MB to 120MB), improves build caching, and removes build tools and vulnerabilities from the production container.
</details>

<summary><strong>ClusterIP vs NodePort.</strong></summary>

**Answer:**
*   **ClusterIP (Default):** Exposes the Service on an internal IP accessible **only within the Kubernetes cluster**. Used for inter-service communication (backend APIs, internal databases).
*   **NodePort:** Exposes the Service on each Node's IP at a static port in the range `30000-32767`. Traffic sent to `<NodeIP>:<NodePort>` is forwarded to internal pods. Used for direct debugging or exposing services behind external physical load balancers.
</details>

<summary><strong>I have an ECR repo and we have Docker images on-premises. How will you pull those images? What are the steps we do in the manifest file?</strong></summary>

**Answer:**
To pull images from AWS ECR into an on-premises Kubernetes cluster:
1. **Generate AWS ECR Login Token:**
   ```bash
   aws ecr get-login-password --region <region> | docker login --username AWS --password-stdin <aws_account_id>.dkr.ecr.<region>.amazonaws.com
   ```
2. **Create Kubernetes `docker-registry` Secret:**
   ```bash
   kubectl create secret docker-registry ecr-secret \
     --docker-server=<aws_account_id>.dkr.ecr.<region>.amazonaws.com \
     --docker-username=AWS \
     --docker-password=$(aws ecr get-login-password --region <region>) \
     --namespace=<target-namespace>
   ```
3. **Reference the Secret in the Deployment Manifest:**
   ```yaml
   apiVersion: apps/v1
   kind: Deployment
   metadata:
     name: my-app
   spec:
     template:
       spec:
         imagePullSecrets:
           - name: ecr-secret
         containers:
           - name: app
             image: <aws_account_id>.dkr.ecr.<region>.amazonaws.com/my-repo:v1.0.0
   ```
*(Note: Since ECR auth tokens expire every 12 hours, configure an automated CronJob or use AWS IAM Roles Anywhere to refresh the secret periodically).*
</details>

<summary><strong>For authentication, what type of objects do we create in Kubernetes (K8s)?</strong></summary>

**Answer:**
Kubernetes does not have a native "User" object in etcd. Authentication and authorization are handled using:
1. **ServiceAccounts:** Used by applications/processes inside Pods to authenticate with the Kubernetes API server.
2. **X.509 Client Certificates / OpenID Connect (OIDC) / AWS IAM Authenticator:** Used by human users and CI/CD systems.
3. **RBAC Objects:**
   *   **`Role` / `ClusterRole`:** Defines permitted API actions (`get`, `list`, `create`, `delete`) on API groups and resources.
   *   **`RoleBinding` / `ClusterRoleBinding`:** Binds the Role to Users, Groups, or ServiceAccounts.
</details>

Secrets are Kubernetes objects designed to store and manage sensitive information (passwords, OAuth tokens, SSH keys, TLS certificates) decoupled from Pod definitions.

</details>

<details markdown="1">
<summary><strong>What to do if kubelet is not working?</strong></summary>

**Answer:**
Troubleshooting steps when `kubelet` fails on a worker node:
1. **Check Kubelet Status & Logs:**
   ```bash
   sudo systemctl status kubelet
   sudo journalctl -u kubelet -n 100 --no-pager
   ```
2. **Check Container Runtime:** Verify if `containerd` or `cri-o` is running (`systemctl status containerd`).
3. **Check Node Disk & Memory:** Verify disk space (`df -h`) and memory (`free -m`). Kubelet stops if disk pressure or out-of-memory triggers eviction.
4. **Verify Certificates:** Check if client certificates in `/var/lib/kubelet/pki/` have expired.
5. **Check API Server Connectivity:** Verify the node can resolve and reach the Kubernetes API endpoint via port 6443 (`curl -k https://<api-server>:6443/healthz`).
6. **Restart Services:**
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl restart containerd kubelet
   ```
</details>

<details markdown="1">
<summary><strong>Handle memory issues in the manifest file.</strong></summary>

**Answer:**
In Kubernetes manifests, configure memory requests and limits under `resources`:
```yaml
resources:
  requests:
    memory: "256Mi"
    cpu: "250m"
  limits:
    memory: "512Mi"
```
*   **`requests`:** Guaranteed memory allocation scheduled by Kubernetes.
*   **`limits`:** Hard threshold. If a container exceeds its memory limit, the Linux kernel terminates it with **OOMKilled (Exit Code 137)**.
*   **Best Practices:**
    *   Set JVM heap parameters (`-XX:MaxRAMPercentage=75.0`) to avoid JVM memory escaping container bounds.
    *   Implement **Vertical Pod Autoscaler (VPA)** for automated right-sizing.
</details>

Amazon Elastic Kubernetes Service (EKS) is a managed Kubernetes service that runs the Kubernetes control plane across multiple AWS Availability Zones for high availability.

<summary><strong>What is equilibrium index in Python?</strong></summary>

**Answer:**
The equilibrium index of an array is an index `i` such that the sum of elements at lower indices is equal to the sum of elements at higher indices.
```python
def find_equilibrium_index(arr):
    total_sum = sum(arr)
    left_sum = 0
    for i, num in enumerate(arr):
        total_sum -= num
        if left_sum == total_sum:
            return i
        left_sum += num
    return -1

# Example: [1, 3, 5, 2, 2] -> sum left of index 2 (1+3=4) == sum right of index 2 (2+2=4) -> returns 2
```
</details>
