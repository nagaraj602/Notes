  1. **Multi-Environment ECR Tagging Strategy:** Never tag images with just a commit hash. Use semantic multi-environment tags:

     - In AWS, there is no static username and password.      - The login command is executed **programmatically within the pipeline step (via Jenkins Shared Library) on every single build**.
     - No engineer ever logs into the Jenkins server manually. Because the pipeline executes `aws ecr get-login-password` dynamically during each execution, the token is always fresh and never expires during build operations.

* **Instructor's Suggestion / Advice:**
  - **On Metrics vs Logs:** Do not confuse metrics with logs. ElasticSearch and Kibana are for logs. API calls (how many are coming in, from where, response codes, latency) are metrics. You must have basic knowledge of how metrics are collected since it should be part of the configuration and deployment.
  - **On handling unknown answers:** If you don't know something, do not say random technical words. If you mention "API dashboards," the interviewer will ask how you collect API metrics. It is much better to honestly state: "This is the only basic thing I set up. We don't have an extensive dashboard currently, but work is in progress to add more features."
* **Guidance / Expected Answer:**
  1. **Dashboards Maintained:**
     - **Infrastructure Level:** Node exporter metrics (CPU/Memory saturation, disk I/O, network bandwidth).
     - **Kubernetes Pod Level:** Pod restart loops (`kube_pod_container_status_restarts_total`), OOMKilled events, container CPU throttling.
     - **Application & API Level (RED Method - Rate, Errors, Duration):** Incoming API request rates (RPS), HTTP 4xx/5xx error rates, and p95/p99 latency percentiles across microservices.
  2. **End-to-End Metrics Collection & Storage Lifecycle:**
     - **Exposition:** Microservices instrumented with Prometheus client libraries (e.g., Spring Boot Actuator with Micrometer or Prometheus Go client) expose metrics over HTTP at `/actuator/prometheus` or `/metrics`.
     - **Scraping:** The Prometheus Operator uses `ServiceMonitor` Custom Resources to discover Kubernetes pods via labels and scrape their `/metrics` endpoint periodically (every 15–30s).
     - **Storage:** Prometheus writes scraped time-series data into its local TSDB (Time Series Database) backed by EBS volumes (or forwards to Amazon Managed Prometheus / Thanos for long-term retention).
     - **Visualization:** Grafana connects to Prometheus as a DataSource and executes PromQL queries (e.g., `sum(rate(http_requests_total{status=~"5.."}[5m])) by (service)`), rendering real-time graphs and triggering alert thresholds.
  3. **Metrics vs. Logs Distinction:** Metrics are structured numeric aggregates measured over time (counters, gauges, histograms) stored in TSDB; Logs are discrete event messages containing stack traces and string payloads stored in Elasticsearch/OpenSearch.
